# Audit des six Companions et matrice de réutilisation

Audit figé au 4 novembre 2026. SHA exacts dans [sources.json](sources.json).
Les liens ci-dessous sont immuables, à une ligne précise ; symboles et SHA-256 sont aussi enregistrés
pour une vérification automatique dans [anchors.json](anchors.json).

## Sens des statuts

- **Opérationnel** : seulement le scénario nommé a été réexécuté avec succès. Un test fixture ne valide pas l’interface.
- **Partiel** : composant inspecté et/ou sous-chemin testé, mais pas la chaîne complète demandée.
- **Absent** : pas disponible dans la version/le mode explicitement nommé.
- **Non vérifié** : absence de preuve d’exécution pertinente ; aucune conclusion de bon fonctionnement.

111 tests d’autorité/formules, 7 tests d’intégration DOM/WebSocket V5 et 8 tests du protocole ont passé dans ce lot.
Les 7 tests chargent les vrais HTML des six Companions avec jsdom et le serveur canonique : ce n’est ni Safari,
ni une mesure de beauté, de fluidité ou de rendu graphique. Rapports et commandes : [validation](../validation/LOT0.md).

## Synthèse par Companion

- **Brack** : le dashboard est la meilleure base de hiérarchie pour Kobe : identité/PV fixes, rail de ressources,
  actions rapides et coûts visibles. Les nombreuses surcharges CSS et le rendu global déconseillent une copie totale.
  Beauté/rapidité sont des objectifs visuels, pas certifiées par le code ou jsdom.
- **Samoth** : grimoire classé par niveaux et rôles, fiches complètes, emplacements corrigibles, calculs par niveau.
  Les métamagies/DD nominatifs et variantes maison ne doivent pas passer chez Kobe.
- **Zéphyr** : bons modèles de choix des bénéficiaires et d’effets de soutien ; certains chemins passent par
  `RPGHealth.online()` et ne sont donc pas un moteur autonome réutilisable tel quel.
- **Kentaro** : receipts, contexte de touche et identification des triggers sont utiles ; les objets et patrons restent nominatifs.
- **Rufus** : réaction, révision d’attaque et ressources à dépense différée sont de bons cas de test ; distinction
  consentement local / autorité finale essentielle pour le mouvement du Manteau.
- **Nans** : défenses/CA/dégâts dérivés des états sont utiles ; la fonction brute `applyDamage` absorbe les PV temp,
  elle n’est pas à elle seule un moteur universel de résistance.

Les anciens rapports citent parfois `Nans/rpg-nans-client.js` : **ce fichier n’existe pas dans le main audité**.
La vraie référence est `index.html` et les modules d’autorité Encounter. Aucun emplacement n’est repris sans vérification.
